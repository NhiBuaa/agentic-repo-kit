# Specifications

Specifications define durable required behavior.

A Specification answers:

> What must be true?

It does not answer:

> How will the current task implement it?

Implementation plans belong under `.agents/plans/` when needed.

Recommended validity states:

- `draft`
- `accepted`
- `superseded`

Do not mirror Issue/PR progress such as `implementing`, `80% complete`, or `blocked` inside specification status.

Starter template: `templates/spec.md`
