# Agent References

Store non-authoritative supporting material that helps coding agents perform work consistently.

Examples:

- implementation examples;
- external API usage notes;
- checklists;
- patterns worth consulting;
- short tool or framework references.

References may point to canonical project documentation, but they must not silently become the owner of architecture, product behavior, or normative implementation rules.

If a reference becomes durably authoritative, promote that information to the appropriate `docs/` category.
